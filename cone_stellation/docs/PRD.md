## ConeSTELLATION PRD (최신)

### 제품 개요/비전
- ConeSTELLATION은 Formula Student Driverless 차량을 위한 콘(Cones) 기반 Graph SLAM입니다.
- 희박(sparse) 관측 환경(프레임당 2~10개 콘)에서도 안정적인 전역 일관 지도와 주행용 상태를 제공하기 위해, 프레임 내 공관측(convisibility)을 활용한 인터-랜드마크 제약과 보수적 ISAM2 최적화를 채택합니다.
- GLIM의 모듈화/비동기/설정·로깅 철학을 학습·도입해 유지보수성과 성능·안정성을 단계적으로 향상합니다.

### 문제 정의
- 고속 주행과 희박 랜드마크로 인해 일반적인 포인트클라우드 SLAM의 전제(밀집, 풍부한 대응)가 성립하지 않습니다.
- 센서/알고리즘 오차, 색상 분류/트래킹 불확실성, 이동/쓰러진 콘 등 동적 요소에 강건해야 합니다.
- 제어(≥100Hz)와 매핑(10~30Hz)의 주기/지연 요구가 상이하므로, 역할 분리와 QoS/스레딩 설계가 필요합니다.
- 최고 주행 속도는 이론상 50 km/h 수준으로 가정합니다.

### 대상 사용자
- Formula Student Driverless 팀, 자율주행 연구자, 희박 랜드마크 기반 내비게이션 응용, 교육/연구기관.

## 요구사항

### 기능 요구사항
1) 입력/출력 인터페이스(ROS2)
- 입력: `/cones/fused/ukf`(탐지/트랙ID/색상/신뢰도), `/odometry/filtered`(EKF 추정)
- 입력(오도메트리 소스): `src/INS/gps_imu_fusion`에서 퍼블리시되는 융합 결과를 사용 (시간동기 필수)
- 출력: `/slam/pose`(map), `/slam/odometry`(odom 기준 보조), 시각화 마커들(`/slam/*`), TF(`map→base_link_slam`, `map→odom`)

2) 전처리/데이터 모델
- 관측 유효성(거리/신뢰도), 간단 라인 패턴 감지, 트래킹 ID 유지, 관측 공분산 모델링.
- 관측은 차량 프레임 2D 상대좌표를 기본으로 사용합니다.

3) 데이터 연관
- 최근접 + 색상 제약 + 트랙ID 보너스. 마할라노비스 게이팅 도입: $d_M^2 = \nu^\top S^{-1} \nu \le \chi^2_{0.95,2}$
- 텐터티브(임시) 랜드마크 누적 후 승격(관찰수/시간/분산/색신뢰도 기준)으로 오연관 억제.

4) 오도메트리(선택적)
- `AsyncConeOdometry`로 프레임간 상대변환 추정. 결과는 키프레임 초기값/속도 추정에 활용.
- 제어는 외부 EKF가 담당하고, SLAM은 글로벌 정합/지도에 집중.

5) 매핑/최적화(ISAM2)
- 포즈(Pose2)·랜드마크(Point2) 변수, Prior/Between/관측/인터-랜드마크 요인 업데이트.
- 인터-랜드마크 거리 요인: $$ r = \|\ell_j - \ell_i\| - d_{ij} $$ 중복 생성 방지(쌍 레지스트리) 필수.
- 패턴 요인(라인/각/평행)은 Jacobian 구현/검증 후 점진 활성화.

6) 루프 클로저(설계/점진 구현)
- 별자리(Constellation) 기술자 + 경로 곡률 특징 + RANSAC 변환 추정. False loop 억제 전략 포함.

7) TF/프레임 정책
- `odom→base_link`는 EKF(INS/GNSS 융합)가 고주기로 발행, `map→base_link_slam`은 SLAM이 발행, `map→odom`은 SLAM이 책임(드리프트 보정). 충돌 금지.
- 센서→기체(T_BS)는 파라미터/URDF로 명시, TF 조회 실패시 백오프/진단 로그, 항등 사용은 일시 완화책.

8) 시각화/디버깅
- 랜드마크/요인/키프레임/경로를 RViz에 퍼블리시. 성능/상태 로그 스로틀/레벨 일원화.

9) 설정/패키징
- YAML 파라미터. `package.xml`에 `tf2`, `tf2_eigen`, `tf2_geometry_msgs` 명시. GTSAM(≥4.2). TBB 의존 시 `find_package(TBB)` 및 `TBB::tbb` 링크.

### 비기능 요구사항
- 정확도: 트랙 1km 대비 드리프트 < 0.5 m, 콘 위치 < 0.3 m, 방향 < 2 deg (목표)
- 실시간성: 제어 100 Hz(EKF), SLAM 10~30 Hz, drift correction 지연 < 50 ms, 50 km/h에서 안정 작동
- 확장성: 500 m 코스, 200+ 콘, 10랩 이상
- 모듈성/유지보수성: 모듈 경계 명확, 테스트/문서화, CI, 파라미터 일원화

## 핵심 설계/원리(요약)
- 관측 모델(차량 프레임): $$ z^{pred}_{k,j} = R(\theta_k)^\top(\ell_j - p_k), \quad r = z^{pred}_{k,j} - z_{k,j} $$
- 오도메트리(Between): $$ \Delta p = R(\theta_{k-1})^\top(p_k-p_{k-1}),\; \Delta\theta = \mathrm{wrap}(\theta_k-\theta_{k-1}) $$
- 인터-랜드마크 거리: $$ r = \|\ell_j - \ell_i\| - d_{ij} $$ (근접 특이점, 중복 제약 방지)
- 텐터티브 승격: 관찰수/시간/분산/색신뢰도 임계 충족 시 확정, 초기 앵커에만 Prior 강제.

자세한 수학/튜닝은 `glim_to_cone_stellation_review_ko.md` 부록 참조.

## Inter-Landmark Feature 심화 분석 및 운용 전략

### 문제 배경과 핵심 아이디어
- 희박 관측 환경에서 포즈-랜드마크 단일 관측 요인만으로는 기하 구속이 약해 드리프트가 누적됩니다.
- 같은 프레임에서 함께 관측된 확정 랜드마크들 사이의 상대 기하(거리/정렬/평행/각)를 제약으로 넣어 국소 형상을 유지합니다.

### 수학적 모델(거리 제약 중심)
- 두 랜드마크 $\ell_i, \ell_j$가 프레임 $k$에서 함께 관측되었고, 현재 추정치의 거리 $\hat d_{ij}$가 물리적으로 신뢰가능하다면 거리 제약을 추가:
  $$ r_{ij} = \|\ell_j - \ell_i\| - \hat d_{ij}, \quad J_i = -\tfrac{(\ell_j-\ell_i)^\top}{\|\ell_j-\ell_i\|},\; J_j = +\tfrac{(\ell_j-\ell_i)^\top}{\|\ell_j-\ell_i\|} $$
- 노이즈 $\sigma_d$는 관측 기하/속도/센서 신뢰도에 따라 스케일링(예: 0.05~0.2 m)하며, 오연관 가능성이 높을 때는 Huber/Tukey 등 로버스트 커널 적용.

### 생성 정책(권고)
- 게이팅/승인 조건:
  - 공관측 카운트 $c_{ij} \ge c_{min}$ (권장: $\ge 2$~3)
  - 거리 범위 $d_{min} \le \hat d_{ij} \le d_{max}$ (권장: $d_{min}=0.3$ m, $d_{max}$는 트랙 폭/콘 간격 근거, 10 m 기본)
  - 색상 호환(둘 다 UNKNOWN이 아니면 일치 필요)
  - 시간/공간 다양성: 너무 인접한 연속 프레임에서 반복 생성 금지(레이트 리밋)
- 중복 방지:
  - `(min(i,j),max(i,j))` 키로 생성 레지스트리 유지. 프레임/시간 윈도우별 1회 생성 원칙.
  - 요인 재가중치/치환: 동일 쌍에 대한 다수 요인을 누적하지 말고, 신뢰도 향상 시 최신 요인으로 교체.
- 스케줄링:
  - 관측 요인과 오도메트리 요인을 먼저 누적한 뒤, $K$ 프레임마다(예: 5~10) 인터-랜드마크 제약을 배치 반영 → 수치 안정성 향상.

### 효과와 한계
- 장점: 관측 수가 적어도 지역 형상을 고정해 누적 드리프트를 억제.
- 한계: 오연관 시 국소 형상을 잘못 고정 → 반드시 강한 게이팅/로버스트 커널/중복 방지로 보호.

### 활용 시나리오
- 직선 구간: 거리/평행 제약으로 차선 유사 구조 유지.
- 코너/치케인: 각/정렬 제약으로 회전부 형상 유지(단, Jacobian 구현 후 점진 활성).

## 실데이터 대응: 데이터 연관과 키프레임 정책(개선안)

### 데이터 연관(강건화)
- 1차 게이팅: 유클리드 거리 + 색상 호환 + 속도 기반 예상 이동(관측 예측) 범위.
- 2차 게이팅: Mahalanobis 거리 $d_M^2 = \nu^\top S^{-1}\nu \le \chi^2_{0.95,2}$, $S=HPH^\top+R$.
- 점수: $\text{score} = d + w_c\,[\text{color mismatch}] - w_t\,[\text{trackID match}]$, Hungarian/JCBB로 전역 일치.
- 트랙ID 신뢰도: 최근 $N$ 프레임 매칭 비율로 가중. UNKNOWN 색상일 때 트랙ID 가중을 상향.
- 동적 콘 검출: 단기간 급격 이동/반복 미매칭 콘은 임시 제외(블랙리스트 윈도우).

### 키프레임 생성(적응형)
- 기본 임계: $\|\Delta p\| > T_{trans}$ 또는 $|\Delta\theta| > T_{rot}$
- 적응형 조정: 속도 $v$에 비례하여 $T_{trans}=a+bv$, $T_{rot}=c+dv$ (고속 시 더 큰 시차 요구)
- 가시성/정보 기준: 관측 수 $\ge N_{min}$, 관측 방향 엔트로피 증가, 포즈/랜드마크 공분산 감소 기대치 기준 추가.

## TF 아키텍처/통합 지침(INS/EKF 연동)

### 역할 분리
- EKF(INS/GNSS): `odom→base_link`를 고주기(≥100 Hz)로 발행.
- SLAM: `map→base_link_slam`과 `map→odom`(드리프트 보정)을 발행. `odom→base_link`는 발행 금지(순환 방지).

### 구현 권장 절차
1) 초기화: `map→odom = I` 한 번만 게시. 이후 드리프트 매니저로만 업데이트.
2) SLAM 최적화 결과에서 `T_map_base` 추정 → 오도메트리 버퍼에서 같은 시각 `T_odom_base` 보간 → $T_{map\,odom} = T_{map\,base}\, T_{odom\,base}^{-1}$
3) 저주파(5–10 Hz)로 `map→odom` 업데이트 게시. 타임스탬프 일치.
4) 진단: TF 체인 일관성 검사, 루프 감지(동일 변환의 양방향 게시) 방지.

### 흔한 오류와 회피
- SLAM이 `odom→base_link`를 동시 게시 → 충돌. 금지.
- `map→odom`을 고주기로 흔들리게 업데이트 → 제어 불안정. 저주파/저노이즈 업데이트 권장.

## 저주파 SLAM 오도메트리 + IMU/GNSS 강결합(설계 제안)

### 목표
- EKF가 고주기 `odom→base_link`를 유지하는 동안, SLAM은 저주파지만 정확한 `map→base_link_slam`/`map→odom`을 제공해 암묵적 루프클로징 효과와 누적 드리프트 억제를 노립니다.

### 설계 원리(GLIM에서 학습)
- IMU 프리인터그레이션 + 고정지연(Fixed-lag) 스무더: 최근 $W$초 창 내 상태만 유지/최적화하며, 창 밖 상태는 마지널라이즈해 실시간성 확보.
- 상태 벡터(예): 최근 키프레임 포즈들 $\{x_k\}$, IMU 속도 $v$, 바이어스 $b_{a,g}$.
- 요인: IMU 프리인터그레이션, 관측(콘), 오도메트리(프레임 간), 필요 시 GNSS 절대 위치(약한 prior).

### 수식 개요
- IMU 프리인터그레이션(요약):
  $$\Delta R,\, \Delta v,\, \Delta p = f(\{\omega_t, a_t\}, b_g, b_a)$$
  $$r_{IMU} = \begin{bmatrix} \mathrm{Log}(\Delta R\, R_i^\top R_j) \\ R_i^\top(v_j - v_i - g\Delta t) - \Delta v \\ R_i^\top(p_j - p_i - v_i\Delta t - \tfrac{1}{2}g\Delta t^2) - \Delta p \end{bmatrix}$$
- 바이어스는 느리게 변하는 상태로 포함, GNSS 팩터(선택)는 위치 차이 잔차를 추가.

### 구현 포인트
- ConeSTELLATION에 IMU 통합을 추가하는 경우:
  - `EstimationFrame`에 $v$, $b_{a,g}$를 활성 상태로 포함.
  - 키프레임 간 IMU를 프리인터그레이트하여 IMU 팩터 추가.
  - 창 길이 $W$(예: 5–10 s)로 고정지연 스무더를 운용, 창 밖 포즈/바이어스는 마지널라이즈.
  - GNSS(있다면) 절대 위치 팩터를 저주파로 삽입하여 전역 드리프트 억제(허용치 작은 대각 노이즈).

### base_link_slam 프레임 운용
- SLAM 포즈는 `map→base_link_slam`로만 게시하여 제어와 분리(제어는 `odom→base_link`).
- `map→odom`은 위 스무더 결과와 EKF `odom→base_link` 보간으로 산출(드리프트 보정).

### 장점/주의
- 장점: 고주기 제어를 해치지 않으면서 저주파이되 정확한 전역 추정 제공, 루프클로저와 결합 시 안정된 지도.
- 주의: 프리인터그레이션 파라미터(노이즈/중력/정렬), IMU-기체 캘리브레이션, 시간동기 오류에 민감.

## 명시적 루프 클로저(GLIM vs ConeSTELLATION) 비교 및 설계

### GLIM의 접근(요약)
- 서브맵 기반 글로벌 매핑 + 명시적 루프 후보 탐색(거리/중첩/스캔매칭/DBoW/ScanContext 등 확장 모듈) → Between/Matching 코스트 요인 추가.
- Fixed-lag/ISAM2로 점진 최적화. 강력한 특징(점군)과 다중 센서(IMU)로 후보 신뢰도 높음.

### ConeSTELLATION의 제약/전략
- 제약: 입력이 콘들뿐이라 특징이 희박하고 외관 특징 부재. 색/상대 배치(별자리)만 사용 가능.
- 전략: “암묵적 루프”(inter-landmark로 드리프트 억제) + “명시적 루프”(별자리/경로/GNSS 게이팅) 병행.

### 명시적 루프 설계(권장 파이프라인)
1) 게이팅(저비용)
   - 위치/자세 근접: $$\|\hat p_i - \hat p_j\| < d_{gate},\quad |\Delta\theta| < \theta_{gate}$$
   - GNSS(옵션): $$\|p^{GNSS}_i - p^{GNSS}_j\| < d^{GNSS}_{gate}$$
   - 시퀀스 간격: 최근 $N$ 키프레임 제외(근접 프레임 금지)
2) 별자리 디스크립터 매칭
   - 거리/각도 히스토그램 유사도 + 색상 분포 + 가시 콘 수 조건
   - 상위 K 후보만 다음 단계로
3) 변환 추정(RANSAC+Kabsch, 2D)
   - 잔차: $$\|R\,p^i_k + t - p^j_{\pi(k)}\| < \epsilon$$
   - SVD 기반 닫힌형 회전/이동 추정, 인라이어 비율이 임계 초과 시 수락
4) 그래프에 루프 요인 추가
   - 포즈 Between 요인(루프 클로저) + 필요 시 일부 랜드마크 정합 보조 요인
   - 로버스트 커널 적용, 중복 루프 방지 레지스트리 운영
5) 최적화 트리거
   - `optimize_on_loop_closure=true` 경로 활성화, 저주파 재최적화

### 수식(2D Kabsch 요약)
- 중심화: $$\bar p = \frac{1}{n}\sum p_k,\; \bar q = \frac{1}{n}\sum q_k$$
- 공분산: $$H = \sum (p_k-\bar p)(q_k-\bar q)^\top$$
- SVD: $$H = U\,\Sigma\,V^\top,\; R = V\,U^\top,\; t=\bar q - R\,\bar p$$

### 파라미터 가이드(초기값)
- $d_{gate}=5$~$15$ m, $\theta_{gate}=10^\circ$~$25^\circ$, $\epsilon=0.5$~$1.0$ m, 상위 후보 $K=3$~$5$
- 히스토그램 bin 수(거리/각): 16~32, 최소 공통 콘 수: 4~6

### 통합 메모
- 기존 `LoopClosureDetector` 골격을 사용해 디스크립터/게이팅/검증을 채우고, 성공 시 포즈 Between 요인으로 반영.
- GNSS가 있을 경우 약한 절대 위치 팩터로 전역 드리프트 억제(루프 실패 대안).
